# 战斗即时划斩与原地蓄力

2026-09-13 用户要求：战斗划动即时触发；杀伐按住不动蓄力，并明确选择“蓄好后划出去重斩”。

## 输入规则

- 普通战斗划动在下一帧释放当前尚未结算的路径，鼠标或手指无需松开。多次移动事件合并处理，后续路径从上一段终点衔接，松手只结算未释放的尾段。
- 杀伐只有起笔原地按住时蓄力。屏幕位移 4 像素以内容忍手抖；超过后固定已蓄时长。0.4 / 0.8 / 1.2 秒三档沿用原数值。
- 蓄力只用于第一段实际划出的攻击，随后继续划动为快刀。移动车程和移动后的等待都不再累计蓄力，重新按下才开始下一次蓄力。原地按住后直接松手不会放空刀。
- 实际释放沿用游戏现有报价、灵力不足降档、狂书透支与伤害结算。起笔不扣钱；新路径释放时扣费，满蓄追加投入只支付一次。取消不会撤销已完成的伤害与付款，未释放路径丢弃；资金不足的旧路径不会因稍后回灵而补播。
- 召唤点按指挥的手抖容差保留。起笔选中迁阵阵心仍在松手确认落点时进行一次迁阵交易；准备期画阵仍待图形闭合后确认；停时大招仍暂存整笔并在截止时齐发。
- 普通流式攻击直接调用施法入口，途中经过其他阵心不会被误识别成迁阵。持笔期间保留场景的绘制标记，镜头不会在新路径坐标采样时突跳。

## 验证

- 输入相关九个测试文件 99 条通过，包含三流派即时付款、蓄力只消费一次、移动不蓄力、取消清理、低灵力不补播、召唤点按、先手加速蓄力不误变指挥、迁阵、停时和镜头定位。日志：`artifacts/input-change/input-tests.log`。
- 浏览器使用真实鼠标拖动：普通划动产生的三次结算均发生在 pointerup 之前；0.83 秒持笔后第一段为二档重斩，1.47 秒持笔后第一段为三档破军，后续均为零档。满蓄四单位附近的实测路径总扣费 7.78（实际屏幕端点换算后的长度略低于四单位），未在松手重复扣费。证据：`artifacts/input-change/browser-proof.json`。
