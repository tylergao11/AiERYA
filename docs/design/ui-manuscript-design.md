# 手绘纸笺 UI

2026-09-13。本页记录第一轮纸笺改造。最新基准升级为整幅暖色卷轴、流派插画和朱砂山纹边界，见 [通用 UI 与转场验收](common-ui-and-transitions.md)；最新素材及精确提示词保存在 `visuals/warm-scroll-v2/`。

本页的通用窗口、转场和手机点击流程补充见 [通用 UI 与转场验收](common-ui-and-transitions.md)。

## 视觉与文案

- 战场保留深靛森林；技能和天赋采用暖色纸笺、大幅水墨插画与书法标题。
- 朱砂笔触用于入山、迎战；红色「定」章表示已经选择，金边表示正在预览。两种状态相互独立。
- 常显信息限于名称、核心效果、必要数值、选择数及生效条件。完整机制折叠在「详情」中。
- 删除重抽解释、重复操作教学、演示过程字幕和泛化提示。保留资源不足等实际操作反馈。
- 战斗卡牌下方的实时说明整区隐藏，避免文案出现、换行或消失导致底栏上下移动。当前选中反馈使用金边，所有卡牌保持相同基线。

## 已接入页面

1. 先天气运：左侧实时演示，右侧五张天赋纸笺；纯点击操作：点卡牌查看演示，点「选定」盖章；点「取消选择」或底部已选槽移除。选满仍可查看其他卡牌。底部双槽、计数、重抽与入山。
2. 此战有悟：三张等高奖励卡；独立插画、核心收益、待生效条件、折叠详情。底部仅重抽次数和构筑入口。
3. 战斗：五行手牌、朱砂迎战按钮、紧凑资源显示和命签构筑入口；纸笺样式同步到构筑中的天赋卡。

## 资源和代码

- `src/ui/manuscript.css` 在既有样式后加载；`src/ui/manuscript-art.ts` 管理图集映射与奖励短文案。
- `elements.webp`：3 × 2，木、火、土 / 金、水、五行循环。
- `talents.webp`：3 × 3，一笔三锋、留痕成刃、借灵 / 双古阵、阵中藏灵、移山换阵 / 双生伴灵、拟法之灵、祖兽。
- `rewards.webp`：3 × 3，驭令、追猎、灵力 / 营火、剑势、漩涡 / 蒸汽、阵势、逆脉。
- `paper.webp` 为纸纹，`cinnabar.webp` 为朱砂按钮。按钮源图实际为 RGB 中性底，运行时通过 `ink-filters.svg` 去除中性底；文字单独绘制。图集无需拆图。
- 五张 WebP 共约 2.26 MB。原 PNG 和生成记录不进入前端产物。
- 书法字体为 OFL 授权的 Ma Shan Zheng。完整源字体和许可证随项目保存；运行时 WOFF2 取源代码使用字的子集，新增文案后运行 `python scripts/subset-ui-font.py`。需要 `fonttools` 和 `brotli`，也可将依赖目录作为脚本参数。
- `BirthPreview` 通过可选镜头回调保留局部演示取景，避免战斗特写恢复镜头时把演示缩回全图。

## 验证与复现

`artifacts/visual-review/manuscript.html` 使用真实组件和固定候选，可通过 `state=birth`、`state=reward`、`state=battle` 进入审查场景。画面证据位于 `artifacts/visual-review/manuscript/`。审查服务器配置关闭 HMR，避免其他正在进行的项目编辑重置审查状态；正式入口仍为项目首页。

- `npm run build` 通过。
- 全量 600 项检查中 595 项通过，5 项耗时模拟达到默认 5 秒上限；将这 5 项所在的 3 个文件用单进程、30 秒超时复跑，26 项全部通过。
- UI、开局抽取、实时演示、奖励示例与随机机制、杀伐及布阵镜头相关 7 个文件共 70 项检查通过。
- 浏览器验证选择两项、第三项拦截、取消、入山、重抽耗尽、完整机制展开；检查桌面、窄竖屏与低横屏布局。
- 1280 × 720 实际战斗中，施法前后与切换五行后的牌组顶部均为 564 px；实时说明区始终 `display: none`。

生成模型输出存在微小纸纹与笔触差异；新增图集沿用本目录批准参考和同一纸色。移动端奖励卡允许纵向滚动，底部操作保持可达。
