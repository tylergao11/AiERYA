# 波次结束清理修复

## 根因与复现

`World.tick()` 在非战斗阶段提前返回，尸体的 `age` 递增和 2.1 秒回收都在返回之后。最后一只狼死亡后立即切入 `rest` 或 `won`，最后几只狼的尸体因此一直留在 `world.wolves`。渲染继续读取这些实体，但死亡帧停住，表现为阵法中残留一只站着的狼。

修复前，以真实出生节奏跑第一波、通过正式伤害接口击杀后，进入 `rest` 时仍残留三只死亡实体，死亡时间分别为 1.33 秒、0.7 秒和 0.033 秒。新增测试在旧代码上复现失败。

## 处理

- 从 `battle` 离开时清空本波敌人，再通知奖励界面与其他阶段监听器；胜利、波间和失败共用这个退出边界。
- 清理不会再次结算击杀、伤害或掉落，也不会删除阵法、恢复土墙生命或移除持久宝宝。现有波末逻辑继续释放宝宝目标和临时战斗机制。
- 战斗未结束时，死亡动画和 2.1 秒回收仍按原规则执行。
- 绘制输入监听阶段切换，立即取消未完成划线及撤阵预览，避免等待下一次鼠标事件才清理。

## 验证

`tests/wave-cleanup.test.ts` 覆盖连续三波自然出生与正式击杀结算、奖励事件前清场、下一波布局、最终胜利、战斗中正常尸体回收、阵法与持久宝宝保留、失败清理不增加击杀奖励。绘制测试补充波末手势和预览取消。

全量 26 个测试文件、360 项测试通过；TypeScript 与 Vite 构建通过。

浏览器 5175 预览实测：正常布置六阵并完成第一波，领取领悟后进入第二波准备，场上无狼的残影，六座阵法仍在；宝宝构筑与吞灵进度保留，控制台错误日志为空。
